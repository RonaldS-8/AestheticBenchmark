# ADR-0005：第一版对比：视频上提示词基线对比 DOVER

- 状态：已被 ADR-0011 取代（实现已归档到 `archive/video-dover/`）
- 日期：2026-11-02

## 背景

决定走 LoRA 还是美学头之前，先要知道两件事：不训练的 VLM
加上好的提示词能做到什么程度，以及专门的质量模型 DOVER 是什么水平。
Qwen VL 可以抽帧读视频，DOVER 本来就是视频模型，
所以先在视频上比最直接。

## 决定

- **评测数据**：DIVIDE-MaxWell，即 DOVER 作者发布的 DIVIDE-3k
  超集，有美学、技术、总体三项均分。
  官方训练集 3634 个视频，验证集 909 个。
  - 官方验证集作为我们冻结的评测集。
  - 官方训练集按种子切出一部分作为 val，其余作为 train；
    两者只用来给 B2 / B3 提供少样本示例，不训练。
- **VLM**：`prompts/baseline-v1/` 的 B0–B3，按时间均匀抽帧，
  帧数写在评测配置里；B4 是换模型尺寸再跑一遍。
- **DOVER**：只用预训练权重推理，权重、代码 commit、
  配置文件都锁定哈希。
- **比较方式**：两边各自按分数从高到低排序，交给客户盲评
  （ADR-0006）；有标签时同时计算 SRCC / PLCC。

## 放弃的方案

- 先比照片：DOVER 不支持照片，比不起来。
- 先训练再比：没有基线，就说不清训练带来了多少提升。

## 后果

- 抽帧看不到卡顿和闪烁，VLM 的技术分可能吃亏，看结果时要考虑。
- **待确认**：
  - DIVIDE-MaxWell 的授权条款（目前只用于内部评测）。
  - 分数区间：导入时必须显式指定。
  - 所选 DOVER 权重有没有在这批数据上训练过。
    如果训练过，DOVER 的结果会偏高，需要换权重或在报告中注明。
- 导入流程见 `scripts/import_divide.py`，目录约定见 ADR-0007。
