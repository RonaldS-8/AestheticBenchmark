# ADR-0002：任务形式：打分加一句评语，以打分为主

- 状态：已采纳
- 日期：2026-11-02

## 背景

候选的任务形式有：打分加评语、给出改进建议、从一组里挑最佳。
产品首先需要的是对用户照片和视频排序、筛选，评语是辅助说明。

## 决定

- 输出一个 JSON 对象：`aesthetic`、`technical`、`overall`
  三项 1–5 分，加一句不超过 60 字的中文评语 `comment`。
- 分数在前、评语在后，模型先给分再写评语。
- 门禁只看分数指标（SRCC / PLCC、解析成功率、延迟）；
  评语只做人工抽检，不进门禁。
- 输出严格解析：代码块包裹、多余的键、残缺 JSON 都算失败。
  EVA 双分数解析已按 ADR-0013 先去掉代码块等格式外壳。

## 放弃的方案

- 挑最佳：输入长度随图片数增长，NAS 上不划算；
  而且排序可以从单张打分推出来。
- 改进建议：标注成本高，难以客观评测。

## 后果

- `AestheticOutput` 是唯一的输出契约，训练目标和评测解析共用。
- 美学头没有评语，但分数与 LoRA 路线可以直接对比。
