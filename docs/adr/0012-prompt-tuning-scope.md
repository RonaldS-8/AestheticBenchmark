# ADR-0012：提示词调优用全量 EVA，LoRA 用选出的最佳单图提示词

- 状态：已采纳
- 日期：2026-11-05
- 补充：ADR-0011（数据范围与 LoRA 提示词以本 ADR 为准）

## 背景

ADR-0011 让提示词基线和 LoRA 在同一份 EVA 划分上比较。
提示词本身不训练，没必要再分训练集和测试集；而 LoRA 要回答的问题是
“在最好的提示词上，训练还能再提高多少”。如果 LoRA 用的提示词和
基线不同，提升里就混进了提示词本身的差异。

## 决定

- **调优集**：全部 EVA 图片去掉 B2 的固定示例图，所有基线都评
  这一批（v1：4070 − 3 = 4067 张）。示例按美学均分分位数从 SFT
  训练集里取 k 张，写在 `data/manifests/eva/prompt-tuning/v1.json`，
  不覆盖、只新增版本。
- **选提示词**：每个候选的得分是美学和技术两项 SRCC 的平均；
  解析率低于门槛或相关系数无定义的不参与；并列时报错交人决定。
  所有候选必须是同一调优集、同一模型、同一运行时。
- **LoRA 提示词**：用不带示例的候选（B0 / B1）里得分最高的那个，
  训练数据用它重新生成，训练和评测都用它。B2 作参考基线：
  它每张图要带 k 张示例，训练和 NAS 推理开销都翻几倍。
- **提升怎么算**：在 SFT eval 集（407 张）上，LoRA 的 SRCC / PLCC
  减去同一提示词不加 LoRA 的成绩。后者直接取调优运行里
  属于 eval 集的那部分（`report-eval.json`），不再单独跑。
  两边必须是同一模型、同一像素预算、同一 `max_new_tokens`、
  都在 transformers 上运行，否则报错。

## 放弃的方案

- 调优只用 val 或 eval 集：407 张选提示词噪声大（SRCC 约 ±0.04），
  候选差距小时容易选错。
- LoRA 固定用 `eva-dual-score@v1`：提升里会混进提示词差异，
  也可能浪费掉更好的提示词。
- LoRA 用 B2：每条样本 4 张图，训练和部署都变慢；
  先看单图能做到多少。

## 后果

- 调优集包含 eval 集的图片，所以选出的提示词在 eval 集上的成绩
  略偏乐观；候选只有 2–3 个，这个偏差很小，报告里注明即可。
- `scripts/prepare_eva_sft.py` 不再写死 `eva-dual-score@v1`，
  接受任何图片、不带示例的提示词；`EvaSftSample` 的 system 消息
  改为可选（B0 没有 system 段）。用新提示词要生成新版本 SFT 数据，
  划分随种子不变，eval 指纹不变。
- `scripts/cloud/train.sh` 里的“B0”（基座 + SFT 提示词）与调优运行的
  `report-eval.json` 重复，选定提示词后可以去掉。
- 全量调优需要 GPU：A10 上 B0 / B1 各约半小时，B2 约 1–2 小时；
  本机只做冒烟测试。
