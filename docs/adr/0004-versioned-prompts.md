# ADR-0004：提示词按版本文件夹管理

- 状态：已采纳
- 日期：2026-11-02

## 背景

提示词基线的结果要能复现，也要能和后来的版本对比。
如果直接改文件内容，旧的评测结果就对应不上任何提示词了。

## 决定

- 提示词放在 `prompts/<集合>-v<N>/`，如 `prompts/baseline-v1/`。
- 文件格式：front matter（`id`、`methods`、`media`）加
  `## system`、`## user` 两段；id 形如 `rubric-score@v1`，
  在整个 `prompts/` 下唯一。
- 跑过评测的版本不再改内容，改动就建新版本文件夹。
- 图片、视频和少样本示例不写进提示词文件，组装消息时再插入。

## 放弃的方案

- 用 git 历史管理版本：评测配置里写的 id 无法直接对应到文件。
- 提示词写在代码里：改提示词就变成了改代码，不方便非开发人员修改。

## 后果

- 评测配置和训练配置只记录 `prompt_id`，加载器负责找到对应文件。
- 测试会检查同一集合内各提示词的评分细则保持一致。
